Constitutional layer

The Network Governance Framework.

The constitutional layer of the Verana network. Every Ecosystem Governance Framework on Verana, whether authored by the Council itself (the ECS-EGF) or by any sector ecosystem, MUST respect it.

What the Network GF defines

Scope. The Network GF applies to every participant in the Verana network: Council Members, Observers, Issuer Grantors, Issuers, Verifiers, service operators, user agents, and any Ecosystem Governance Framework (EGF) authored on Verana.

Sections (draft)

  1. Preamble and purpose. The Network GF's authority, the Council's role, and the governing law (Swiss law; Canton of [CANTON] seat).
  2. Permission lifecycle. How permissions are created, validated, suspended, and revoked on the VPR. Required states, required transitions, required public-record trail.
  3. Trust Deposit rules. Minimum deposit sizing per permission type, slashing conditions, refund conditions, deposit-freezing procedure during dispute.
  4. Risk-management rubric. The graduated sanctions process: notice → remediation → suspension → slashing. Applied uniformly across all EGFs. See Risk management.
  5. Dispute-resolution process. Standing for claims, notice requirements, hearing procedure, appeal process. Venue: Dispute Resolution Panel (standing committee); seat: [CANTON], Switzerland. See Dispute resolution.
  6. Requirements for EGFs on Verana. The non-negotiables that every EGF on Verana MUST satisfy. This is the interface between the Network GF and any sector EGF. Examples: EGFs MUST publish their controller DID, MUST respect the Trust Deposit minimums, MUST NOT weaken the risk-management rubric.
  7. Validator operational standards. Uptime, slashing-clean record, key-management practices, upgrade response time. Applied to every Council Member's validator.
  8. Chain-evolution process. How network upgrades are proposed, reviewed, tested on testnet, and adopted on mainnet.
  9. Interface with the ECS-EGF. The ECS-EGF is itself an EGF; it MUST respect the Network GF. This section defines the interaction.
  10. Amendment process. Per the governance-index page.

Full text

The full normative text of the Network GF is maintained at github.com/verana-labs/verana-council-gov/network-gf. Changes are tracked via git; each published version has a permanent URL and a SRI hash.

What the Network GF does NOT define

  • Sector-specific rules. Those live in sector EGFs, authored by the ecosystems themselves.
  • Wallet or agent UX (out of scope).
  • Product fees, pricing, or business models (out of scope).
  • Validator rewards mechanics, out of scope for this site (the economic layer is documented on verana.io).
